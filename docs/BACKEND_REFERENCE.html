SOP Studio 백엔드 레퍼런스

1부는 DB 스키마. 표 5개의 컬럼 하나하나를 "타입 · 뜻 · 누가 쓰나 · 누가 읽나" 로. 2부는 백엔드 파일 14개의 역할과 함수 하나하나. 이 저장소의 실제 코드만으로 씁니다.

DB1. 표 5개는 어떻게 이어지나

sop_documents (문서)  1 ────────── N  sop_versions (버전)  1 ────────── N  flow_nodes  (순서도 상자)
   │  id  ◄────────────────────────── document_id                            └─ ref_document_id ──► sop_documents.id
   │  current_version_id ──────────► id                                  1 ────────── N  flow_edges  (순서도 연결선)
   │                                  content jsonb (편집기 JSON 원본, 복원용)
   └── 1 ── 0..1  sop_edit_locks (편집 잠금)

ON DELETE 규칙
  문서 삭제 → 버전·잠금 CASCADE(같이 삭제) → 버전 삭제 → 노드·선 CASCADE
  가리키던 버전/문서가 사라지면 current_version_id / ref_document_id 는 SET NULL(빈칸)

설계 원칙 4가지. 스키마 파일 머리에 적힌 그대로

  1. 복원은 sop_versions.content 하나로 끝난다. 편집기 JSON 이 통째로 들어 있어서, 나머지 컬럼과 표는 전부 검색·목록용 사본입니다.
  2. flow_nodes / flow_edges 는 파생 사본. 저장할 때 서버가 content 에서 뽑아 넣습니다. 편집기는 이 두 표를 읽지 않습니다.
  3. 버전 행은 불변. 저장할 때마다 새 행 + 새 노드 행. 옛 행은 절대 UPDATE 하지 않습니다.
  4. 참조는 번호가 아니라 id 로. 순서도의 "다른 SOP 상자" 는 ref_document_id(uuid) 가 진짜 연결입니다. 번호는 바뀌어도 id 는 영구라 참조가 안 끊깁니다.

화살표의 ON DELETE 규칙은 두 가지입니다. CASCADE 는 "부모가 지워지면 자식도 같이" (문서 → 버전 → 노드·선, 문서 → 잠금). SET NULL 은 "가리키던 것이 사라지면 빈칸으로" (current_version_id, ref_document_id). 다만 이 앱은 문서를 실제로 DELETE 하지 않고 status='retired' 로만 바꾸므로, CASCADE 는 안전장치이지 일상 경로가 아닙니다.

1.7 스키마 적용과 마이그레이션

python -m app.tools.apply_schema 하나로 두 상황을 처리합니다.

  • 빈 DB (표가 없음) → sql/sop_schema.sql 전체 실행. 새 설치.
  • 표가 이미 있음 → sql/migrations/*.sql 을 이름순(001, 002…)으로 전부 실행. 각 파일은 IF NOT EXISTS / IF EXISTS 로 몇 번 실행해도 안전(멱등).
파일하는 일

pg_trgm 확장이 없거나 만들 권한이 없는 DB 에서는 그 확장을 쓰는 줄만 빼고 실행합니다. 이름 검색은 되고 속도만 다릅니다.

파일별2. 파일 하나하나, 함수 하나하나

각 파일의 함수를 "무엇을 받아 무엇을 돌려주나, 누가 부르나" 로 적습니다. 파란 이름은 HTTP 창구(엔드포인트), 앞에 _ 가 붙은 것은 그 파일 안에서만 쓰는 도우미입니다.

app.py50줄 · 프로젝트 루트

전원 스위치. python app.py 로 서버를 켭니다. Dockerfile 의 ENTRYPOINT 가 이 파일을 부릅니다. 폴더 app/ 과 이름이 같지만 파이썬은 폴더를 먼저 찾으므로 문제없습니다.

main() → None

환경변수 PORT(기본 8000)를 읽고 uvicorn.run("app.main:app", host="0.0.0.0", …) 을 실행합니다. 윈도우면 asyncio 정책을 Selector 로 바꿉니다(psycopg 호환). proxy_headers=True 로 앞단 프록시의 X-Forwarded 헤더를 믿습니다.

부르는 곳: if __name__ == "__main__". 즉 직접 실행할 때만.

app/main.py186줄

식당 문. FastAPI 앱을 만들고 부품을 조립합니다. 순서: 설정 읽기 → 앱 생성(lifespan) → 오류처리기 → 미들웨어 → 라우터 등록 → 헬스체크 → 편집기 HTML 서빙.

lifespan(app)

앱이 켜질 때 db.open_pool() 로 DB 연결 풀을 열고, 꺼질 때 db.close_pool() 로 닫습니다. yield 앞이 시작, 뒤가 종료.

부르는 곳: FastAPI 가 자동으로.

log_and_limit(request, call_next) 미들웨어

모든 요청이 거치는 문. Content-Length 가 20MB 를 넘으면 본문을 읽지도 않고 413. 처리가 끝나면 "메서드 경로 상태코드 걸린시간" 로그 한 줄. CORS 미들웨어보다 먼저 등록해야 413 응답에도 CORS 헤더가 붙습니다.

liveness() GET /health

항상 {"ok": true}. DB 를 보지 않습니다. 컨테이너 플랫폼이 몇 초마다 두드리는 용도라, DB 가 잠깐 흔들려도 서버를 죽이지 않게.

health(response) GET /api/health

db.ping() 으로 SELECT 1 을 날려 봅니다. 성공이면 200 {"ok":true,"db":"up"}, 실패면 503 {"ok":false,"db":"down"}. 배포 후 제일 먼저 열어 보는 주소.

inject_api_base(html, root_path) → str

편집기 HTML 의 <head> 바로 뒤에 <meta name="api-base" content="{ROOT_PATH}"> 를 끼워 넣습니다. 서버가 /sop 같은 접두어 뒤에서 돌 때 프론트가 API 주소 앞에 그걸 붙이도록.

부르는 곳: index().

index() GET /

static/SOP_STUDIO.html 을 읽어 위 meta 를 끼워 돌려줍니다. 파일이 없으면 404 static_not_found.

라우터 3개는 전부 prefix="/api" 와 dependencies=[Depends(current_user)] 로 등록됩니다. 나중에 current_user 에서 401 을 던지면 API 전체가 한 번에 보호됩니다.

app/config.py149줄

환경변수를 읽어 Settings 상자에 담습니다. 코드에 DB 주소를 직접 적지 않아서 같은 코드를 개발 PC 와 회사 컨테이너에서 값만 바꿔 씁니다.

_env_int(name, default) → int

환경변수를 정수로. 비었거나 숫자가 아니면 기본값.

_env_prepare_threshold() → int | None

DB_PREPARE_THRESHOLD. 빈 문자열이나 0 이면 None = prepared statement 를 안 만듦 (PgBouncer 트랜잭션 풀링 대응).

app/routers/locks.py133줄

같은 문서를 두 사람이 동시에 고치지 못하게. 편집 시작 때 잠그고(POST), 편집 중 주기적으로 같은 요청을 다시 보내 연장하며(하트비트), 끝나면 풉니다(DELETE). 만료 시각이 있어 브라우저를 닫아도 저절로 풀립니다.

acquire_lock(doc_id, body, conn, user) POST /sops/{doc_id}/lock

규칙: 잠금 없음 / 내 잠금 / 남의 만료된 잠금 → 잡음(200). 남의 유효한 잠금 → 423 locked. 트랜잭션 안에서 먼저 문서 행을 FOR UPDATE(잠금 행이 아직 없는 문서에 두 사람이 동시에 오면 "없는 줄" 은 잠글 수 없어 둘 다 INSERT 로 가 중복 오류가 나므로, 항상 있는 문서 행에서 줄을 세움) → 잠금 행 FOR UPDATE → 없으면 INSERT, 있으면 UPDATE. 만료 시각은 now() + make_interval(secs => %s).

release_lock(doc_id, body, user_query, conn, header_user) DELETE /sops/{doc_id}/lock

누가 푸는지는 본문 user → ?user= → X-User 순(DELETE 에 본문을 못 싣는 도구도 있어서). DELETE … WHERE document_id = %s AND locked_by = %s 라 남의 잠금은 지워지지 않음. 이미 풀려 있어도 200(여러 번 불러도 같은 결과).
